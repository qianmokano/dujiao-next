# 统一账户原始字段检查：与 JSON 绑定大小写行为一致

日期：2026-10-03。基线 fork main `d29782b`。这是两站账户面板统一最终验收的保护补充，沿用用户已授权的两站实现、PR、镜像和备份恢复发布流程。

## 结论与依据

- 普通客户与后台托管身份字段已经检查原始 JSON 是否出现，能够整体拒绝小写字段的 null／业务混合请求。
- Go JSON 绑定接受 `Nickname` 等字段大小写变体，原始字段名单只比较小写键会漏掉这种请求。网关个人接口的 null 检查补充期间发现并一并修正。
- 参考商城个人接口 `ShouldBindBodyWith` 加原始字段检查、商城后台身份策略 guard、网关管理员字段出现检查三处已有模式，比较前只对键名转小写，不修改字段值。
- 个人及管理员接口同时覆盖身份别名 `identities`、`identity_bindings`。非统一模式和合法语言／业务修改沿用现有行为；没有新增配置、数据迁移或 Casdoor 修改。
