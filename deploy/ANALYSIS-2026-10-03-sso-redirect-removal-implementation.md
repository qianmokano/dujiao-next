# 页内认证独立化与 OIDC 跳转移除实施

日期：2026-10-03。用户授权覆盖商城及 API 网关的代码、PR、固定镜像发布和生产上线。

## 当前结论与依据

- 从两个 fork 的最新 main 创建 kano/remove-oidc-redirect；商城基线 a8ba284f，网关基线 ffc1f96b。
- 商城页内认证与 OIDC 共用配置、身份收尾和 handler；网关 SSO 依赖 oidc_connect 的地址及启用状态。配置迁移必须先于运行服务装配。
- 身份数据库中的 oidc 提供方标识及网关 issuer/subject 保留，以继续关联原业务用户和原权益规则。
- Casdoor 两应用的公开只读配置均未启用 CAPTCHA。新增页内 Default 图片及 Cloudflare Turnstile 接入，不改生产 CAPTCHA 策略。
- 参考现有密码代理、MFA 挑战、验证码注册、GORM 标记迁移、PostgreSQL 不可变迁移及配置部分更新模式。

## 实施与验证

按配置拆分、跳转链路删除、验证码接入、认证及迁移回归的小步顺序实施。记录测试、CI、发布及验收结果；只提交本次直接产生的文件，不修改任何预存未提交文件。

商城实现已完成第一轮验证：

- `sso_auth` 独立六字段配置与一次性事务迁移；显式关闭及空值、新配置优先、旧行保留、重复启动和数据库错误均以真实 SQLite 验证。
- 页内认证移至 `ssoauth` 模块，保留历史身份标识及账号事务收尾；旧授权、回调、绑定接口及前端回调页面删除。
- 新后台端点 `/admin/settings/sso-auth` 已登记 RBAC；公开配置与三个模板采用新配置。
- 五分钟验证码挑战使用 Redis 原子消费，绑定操作、账号、应用；图片和 Turnstile 与本站验证码分别处理。MFA 挑战绑定应用配置，密码保留原字符，代理拒绝 HTTP 重定向。
- 全量 Go 测试、`go vet ./...`、前后台类型检查及生产构建通过；新增 HTTP 错误与 404 回归随后单独通过。页内认证模块 race 测试覆盖率 90.5%，验证码引擎 93.3%，新增前端验证码组件及状态管理 100%。前台全部测试和后台 30 项测试通过。

2026-10-07 最终回归补充：

- 网关同类改造、真实 PostgreSQL/Redis 迁移与并发消费测试已完成。
- 验证码取消未完成请求时立即清除加载状态；SDK 加载失败允许重新加载，本站与通行证 Turnstile 控件可同时工作。18 项账户回归通过，选定前端逻辑语句及函数覆盖率 100%，分支 98.57%；前台类型检查与生产构建再次通过。
- 隔离 Chrome 覆盖 Classic、Atlas、Vault 三模板及网关的图片、Turnstile、无需验证码登录/MFA，及两站邮箱验证码注册。MFA 完成前无登录令牌；本站和通行证证明分别提交，密码空格不丢失，旧回调显示 404。
- 两站后台均在隔离 Chrome 中实际保存独立通行证设置；商城只提交六字段新配置，不再提交客户端秘密或回调地址。已人工查看三模板、网关和后台截图。
