# 两站账户面板统一：dujiao 实施记录

日期：2026-10-03。基线为 fork main `67f7f30e`，使用现有本地仓库的 `kano/account-panel-unification` 分支。用户已授权两站实施、PR、镜像及上线；先 sub2api、后 dujiao。Casdoor 仅复用已有账户中心，不修改其策略或页面。本记录不包含凭据。

## 已核对的实现

- 密码登录、通行证 MFA 与 OIDC 共用外部身份登录收尾；已有用户更新身份记录而未同步 `User.DisplayName`。
- 共用个人中心 `ProfilePanel` 仍编辑昵称。三模板尚无资料响应中的头像字段，通行证账户入口仍指向 `/login/kano`。
- 本地注册、邮箱验证、域名白名单仍无统一模式职责提示。管理员客户编辑可以写本地身份字段，不同步 Casdoor。
- 参考既有个人中心、安全入口、后台注册／OIDC设置、管理员客户更新与身份仓储／事务实现。

## 实施约定

只在统一模式收拢普通客户身份资料；语言偏好和业务功能保留。昵称与头像元数据事务同步且使用字段更新，区分头像缺失、无效和明确清空；资料响应新增只读 `avatar_url`，不新增数据库列。三模板统一展示并指向 `/account`。后台隐藏不参与统一注册的控件，保留原值；托管身份修改 API 返回 403，混合请求不部分保存。本站管理员认证与恢复独立保留。

## 实施结果

- OIDC 首次关联和重复登录在同一事务内更新身份元数据及昵称。明确空头像清除，缺失、null 和无效 URL 保留已有头像；资料接口从已有身份表返回只读头像。
- 登录时间、语言偏好和后台业务编辑使用字段更新，避免覆盖并发写入的消费、余额、会员等级或身份资料。事务失败不发放登录令牌。
- 客户与后台身份修改在写入前校验统一策略；包含 null 或业务字段的混合请求同样整体拒绝并返回 HTTP 403。后台解绑也受策略约束。策略加载失败时界面保持只读。
- 三套个人中心复用头像组件，加载失败回退首字母；昵称只读，语言偏好仍可保存。账户入口指向通行证 `/account`，提示下次登录同步。
- 后台注册区域改为通行证职责说明与经过校验的只读管理链接；保存其它设置时跳过隐藏的本地注册字段，保留原值。客户编辑仅提交业务字段；独立管理员的认证与恢复保留。

## 验证依据

- `go test ./...`、`go vet ./...`、服务端构建通过；新增真实 SQLite 集成测试覆盖登录重复同步、头像边界、事务回滚、并发业务写入保留、原邮箱／密码／用户 ID 保留。
- 后台前端 30 个测试通过；用户前端全量测试与两端生产构建通过。个人资料和头像组件覆盖率为语句／行／函数 100%，分支 97.36%。实际变更的 Go 语句覆盖率为 81.6%（151/185），不是全仓库覆盖率。
- 新增 HTTP 回归覆盖只读策略、null 和混合请求拒绝、策略读取失败及语言更新。只读链接不进入持久化配置。
- VPS 只读预检：商城当前镜像 `v0.1.0-kano.14` 健康；7 个客户、16 个订单、2 个钱包、7 条外部身份。客户本地 TOTP 的已启用、密钥及待确认数均为 0。网关当前 `v0.2.11-kano.4` 健康，130 个用户中普通客户本地 MFA 为 0。切换前再次核对。
