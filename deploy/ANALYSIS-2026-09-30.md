## 结论与依据

1. 用户端只有一套全局 Toast 组件，具有三种状态样式：成功、错误、普通信息。`frontend/user/src/composables/useToast.ts` 的类型与公共调用入口仅包括 `success`、`error`、`info`，没有 `warning` Toast。
2. `frontend/user/src/components/Toast.vue` 中，成功使用绿色语义色与勾号，错误使用红色语义色与叉号，普通信息使用中性卡片背景与信息图标。三者共用圆角、边框、阴影、背景模糊和进出动画。
3. `frontend/user/src/App.vue` 在所有模板外壳之后统一挂载 `<Toast />`。Atlas 没有独立 Toast 组件；`frontend/user/src/templates/atlas/styles/atlas.css` 通过 `body.atlas-tokens` 为 Teleport 浮层提供模板令牌，调整中性颜色，但不改 Toast 的结构与类型。
4. 桌面端通知位于顶部居中，移动端位于底部居中；默认三秒自动消失。通知可附带操作按钮，该能力属于现有样式的可选内容。
5. 已核对三处实际调用：`useProductDetail.ts` 添加购物车使用成功通知，`useOrderDetail.ts` 取消订单失败使用错误通知，`useCart.ts` 删除商品使用普通信息通知并附带撤销按钮，持续五秒。
6. 页面内 Alert 是另一种呈现方式，`frontend/user/src/utils/alerts.ts` 包含成功、错误、警告三种级别；确认弹窗是需要用户选择的对话框。两者不计入浮动 Toast 的三种状态样式。

## 提示条与 Toast 的当前使用分工

- 页面相关错误与业务状态主要使用提示条：Atlas 登录页将登录错误留在表单中；商品详情页的购买限制使用 `purchaseWarning`；`useCheckout.ts` 的 `checkoutAlert` 汇总提交错误、预览错误及阻止提交的原因；`usePayment.ts` 的 `paymentAlert` 汇总跳转状态、订单取消、订单过期及付款错误。
- Toast 当前集中在三类操作反馈：商品详情与快速购买弹窗中的加入购物车成功、购物车删除商品并提供撤销、取消订单失败。其默认自动消失，适合短暂反馈。
- 现有实现并未完全按反馈持续时间统一：`views/personal/ProfilePanel.vue` 保存资料成功和失败均使用提示条；`views/reseller/ResellerApply.vue` 提交申请成功和失败也均使用提示条。故不能用“成功用 Toast，失败用提示条”概括项目。
- 提示条不会按统一计时器自动消失，而由对应页面的状态变化、再次操作或卸载控制。具体持续时间以每个页面实现为准。
- 后续若统一交互，可以把“是否需要留在页面供用户理解、修正或处理”作为选择依据：权限与订单状态、表单和购买限制保留在页面；轻量操作结果使用 Toast。该原则是根据当前使用场景提出的设计建议，当前代码没有统一强制规则。
- 本次补充仍为源码分析与文档记录，未修改运行行为，未运行测试或构建。

## 实施结论

1. `PageFeedback.vue` 统一成功、错误、警告、信息提示。Atlas 提示条和 Toast 共用中性背景、正文颜色、细边框、10px 圆角、14px 字体和 16px 图标，仅图标使用语义色。提示条无阴影；Toast 使用模板浮层阴影，并限制窄屏宽度、允许长文本换行。
2. `useFeedback.ts` 明确区分轻量成功和短暂操作失败。保存、验证码发送、绑定、API 与推广操作的轻量成功在 Atlas 使用默认三秒 Toast；表单错误、加载错误、权限和购买限制仍持续留在页面。异步结果在所属上下文卸载后不会弹出通知。
3. `useCopyFeedback.ts` 与 `utils/feedback.ts` 为支付链接、支付与充值钱包地址、订单交付内容、推广链接、API Key/Secret、恢复码提供两秒按钮旁勾号与“已复制”。重复或并发复制以最新请求为准；失败清除旧复制成功状态并显示错误 Toast；卸载清理计时器和未完成请求的反馈。Atlas 使用严格剪贴板结果判断，旧模板仍走原有调用路径。
4. 保留购物车删除通知的五秒时长与撤销动作；支付跳转说明、恢复码提醒、密钥展示、礼品卡兑换明细仍在专用区域。修改密码后的结果只保留登录页原有提示，源页面不重复弹 Toast。
5. 推广和 API 操作在后续刷新失败时仅显示页面错误，不同时弹出成功 Toast。API 刷新失败仍保留当前已展示的凭证与新生成密钥，避免丢失只展示一次的内容；旧模板加载处理保持原有路径。
6. 错误提示使用 `role="alert"`，普通状态使用礼貌播报。复制按钮通过内部文字的 `aria-live="polite"` 播报，保留可访问名称和键盘操作。通知文案不包含密钥、恢复码或订单交付内容。
