## 易支付渠道字段核对

- 2026-09-29 核对 VPS 的 `callback_routes_config`，支付回调仍使用默认路径 `/api/v1/payments/callback`。易支付 v1 的通知地址应填 `https://store.kanoapi.top/api/v1/payments/callback`，同步地址应填 `https://store.kanoapi.top/pay`。前者是服务端异步通知，后者是付款后的浏览器回跳页；不要手工添加查询参数。
- `target_currency` 和 `exchange_rate` 只有在网站订单币种与支付网关收款币种不同时一起填写。代码计算方式为订单金额乘以汇率基数，再以目标货币发起支付；同币种留空即可。
- 这些字段仍需通过实际小额支付检查回调与回跳。截图中可见商户密钥，正式启用前应在服务商处轮换；本记录不保存密钥。

## SMTP 发送失败排查

- 后台提示“网络连接失败”。VPS 中已保存 SMTP 配置：`smtp.qcloudmail.com:465`、SSL 开启、STARTTLS 关闭，用户名和密码字段均有值。未读取、输出或修改密码，也未发送测试邮件。
- Nginx 访问日志中 5 次 `/api/v1/admin/settings/smtp/test` 请求均为 499，表示客户端在服务端完成请求前断开。管理端 API 超时为 10 秒；应用 SMTP SSL 连接使用无显式超时的 `tls.Dial`，因此用户看到的是网络错误而非 SMTP 的详细错误。
- VPS 连接 `smtp.qcloudmail.com:465` 和 `:587`、腾讯云其他区域节点的 465，以及 `smtp.exmail.qq.com:465` 均超时；直连目标 IP 也超时。作为对照，本地计算机可连接 `smtp.qcloudmail.com` 的 465/587，VPS 出站 HTTPS 正常。VPS UFW 默认允许出站，iptables OUTPUT 策略为 ACCEPT。故障发生在 SMTP TCP 连接阶段，尚未进入 TLS 或身份验证。现有证据指向 VPS 服务商或上层网络的 SMTP 出站限制；需检查服务商防火墙/安全组与邮件端口封禁策略。
- [腾讯云邮件推送文档](https://intl.cloud.tencent.com/zh/document/product/1084/44457?lang=zh)说明 `smtp.qcloudmail.com` 是香港节点，端口 465；[腾讯云企业邮箱配置说明](https://intl.cloud.tencent.com/zh/document/product/1266/71700)列出的服务器为 `smtp.exmail.qq.com:465`。应先确认使用的产品和区域，再处理出站连通性。恢复连接后再测试账号、SMTP 专用密码与发件地址是否匹配。

## 当前开发与发布工作流

1. 本地在功能分支修改代码并测试，提交后推送到 GitHub fork，发起 PR。PR 上的 `ci` 工作流检查 Go、前端和构建；合并到 `main` 后得到确定的发布提交。
2. 从该 `main` 提交创建一个未使用过的 `v*` 标签并推送。`Publish fork image` 工作流再次执行 Go 与前端测试，通过后发布 `ghcr.io/qianmokano/dujiao-next:<标签>` 的 amd64/arm64 镜像。
3. VPS 不编译源码。更新时先在 `/opt/dujiao-next/.env` 将 `APP_IMAGE` 指向新标签并拉取镜像；停止应用和 Redis 后备份 `config.yml`、SQLite 数据、上传文件及 Redis 数据卷，再执行 `docker compose up -d`。检查容器健康、HTTPS 健康接口及关键业务功能。需要回滚数据库迁移时，应连同旧镜像恢复发布前的数据备份。
4. Nginx、证书、运行密钥、管理员账号和业务数据库由 VPS 保管；日常代码发布不覆盖它们。首次部署已使用 `v0.1.0-kano.1`。本地当前分支 `kano/docker-nginx-deployment` 有未提交改动，尚未进入该线上版本。
